## Context（背景）

现有画像的主导维度是**心理学 preset**：

- OCEAN（大五人格）：O / C / E / A / N
- MBTI：E_I / S_N / T_F / J_P
- Schwartz 价值观（10 个子维度）
- Regulatory Focus：promotion / prevention
- Facts：k-v 自由项

这套 preset 在"了解一个人是谁"上是合理的，**但与 ADR-001 锁定的核心目标——"提升想法→产品转化能力 + 工作改进建议"——并不直接对齐**。OCEAN 的"openness 78"对用户要不要重启某个项目几乎给不出可操作建议；MBTI 在工作判断面前更弱。

同时，画像维度框架本身是 **config-driven 可扩展**的（这是 dimension + backbone 当年留的扩展点）—— 切 preset 不需要动引擎，只是写新的 dimension 配置 + 对应的 analyzer。

## Decision（决策）

引入 **`profile.work.*` 命名空间**作为新的主导 preset，和旧心理学 preset **并存**：

- 新增 6 个工作认知维度（见下表），由新的 analyzer 流水线产出。
- 旧维度（OCEAN / MBTI / Schwartz / Regulatory Focus / Facts）保留：
  - **Schwartz values 和 Regulatory Focus 仍参与建议生成**，作为价值观/动机焦点的补充信号
  - **OCEAN 和 MBTI 停止 analyzer 投入**，已有数据保留只读，演化曲线继续展示，**但不再作为消费侧的主要引用维度**
  - **Facts 保留并扩展**，仍是 k-v 形态
- **不做迁移**。新数据走新 namespace，旧数据保留在原 namespace。两套并行，演化曲线不丢历史。
- 所有 `engram.*` 工具（见 ADR-002）的 cite 优先引用 `profile.work.*`，必要时叠加 values / regulatory focus。

### 新 preset：`profile.work.*` 6 个维度

| 维度 | 形态 | 子维度示例 | 主要 analyzer 思路 |
|---|---|---|---|
| `working_style` | scores（0-100，τ 加权贝叶斯合并） | top_down_vs_bottom_up / planner_vs_explorer / breadth_vs_depth / divergent_vs_convergent | 从 entry 文本中识别"我先 X 再 Y"类执行/思维模式描述 |
| `recurring_blockers` | 模式列表（pattern + 频次 + 最近 N 条 entry id） | category（决策犹豫 / 完成度 / 优先级偏移 / 技术盲区 / 能量低谷 / ...） | 跨 entry 聚类 + 频次衰减；每条 blocker 必须可指向至少 2 条证据 entry |
| `strengths_and_gaps` | 能力地图（capability + score + confidence + 证据） | 写作 / 架构 / 调试 / 沟通 / 估算 / 决策 / 验证设计 / ... | analyzer 读 entry，提取"我做到了 X"和"我又卡在 X"两类信号 |
| `decision_patterns` | scores + 列表 | speed（快/慢） / hesitation_freq / re-decision_rate / regret_rate / commitment_after_decision | 跨 entry 追踪决策语句和后续 entry 中的回顾，统计模式 |
| `interest_trajectory` | 主题热度时序 | topic + 热度（mention 频次衰减） + 趋势 | LLM 抽 topic + 时间序列建模 |
| `facts` | k-v（保留） | occupation / current_projects / tools_in_use / ... | 直接替换合并（无贝叶斯） |

### 不再引入的维度

- 团队/组织维度（汇报关系、团队规模等）—— 这是事实，不是认知，归 `facts`
- 情绪 / mood —— 已有 `entries.mood` 字段承载，不再升维到画像
- 任何"近期事件 / 任务进度" —— 违反 AGENTS.md 硬规则 #1

### 旧 preset 命运表

| 维度 | 状态 | 理由 |
|---|---|---|
| OCEAN | **frozen**：保留数据与曲线，不再投入 analyzer 改进 | 对工作建议直接价值低 |
| MBTI | **frozen**：同上 | 同上 |
| Schwartz values | **active 但次级**：继续合并、参与 cite | 价值观对决策建议有效 |
| Regulatory Focus | **active 但次级**：继续合并、参与 cite | promotion / prevention 对工作风格判断直接有效 |
| Facts | **active**：升级为一等公民，扩展 k 范围 | 是工作建议的硬上下文 |

"frozen"指**不删数据、不改 schema、analyzer 不再迭代**。`ProfileTab` 演化曲线仍然可以看见它们；新工具不主动 cite。

## Consequences（后果）

**锁定的事：**

- 必须为 `profile.work.*` 6 个维度写 6 个新 analyzer（其中 `recurring_blockers` 和 `strengths_and_gaps` 需要跨 entry 聚合，工程上比当前的 per-entry analyzer 重）
- 周报和 `engram.recent_patterns` 工具的核心数据源是 `recurring_blockers` —— 这一维度必须先稳。
- `ProfileTab` 重做时分两个 section：work（主） + legacy psychology（折叠/次屏）。
- 一段时间内画像深度会变浅（新 analyzer 累计样本需要时间），需要忍耐期。

**关闭的可能：**

- 不再追求"心理学画像"叙事，OSS README 里要相应调整定位文案（不再宣传 OCEAN / MBTI 作为卖点）。
- 如果有人 fork 想做"个人心理画像产品"，可以从历史 commit 里提取，但主线不再服务那个故事。

**可接受的副作用：**

- 维度数量增加（旧 4 + 新 6 = 10 类），但只有 4 类（work 4 个 + values + regulatory + facts）参与日常 cite。看似复杂，实际消费面收敛。
- `recurring_blockers` 和 `strengths_and_gaps` 是跨 entry 计算，需要新增 backfill 任务和定期 recompute。

## Alternatives considered（被考虑的替代方案）

1. **保留心理学 preset，仅在工具 prompt 层"翻译"成工作语言。**
   被拒。translation 出来的是噪声鸡汤，且 LLM 在没有真正信号的情况下会编。问题在数据层，不在 prompt 层。

2. **完全替换：删除 OCEAN / MBTI 的 schema 和数据。**
   被拒。删历史等于丢"演化"叙事——演化曲线是 ProfileTab 的核心价值之一，明确保留。

3. **一个超大扁平 preset（把 work 维度直接加到现有 preset，不做命名空间隔离）。**
   被拒。会让维度配置膨胀且语义混乱（"openness"和"breadth_vs_depth"相关但不同），后续要分开重构成本更高。命名空间隔离的成本几乎为零。

4. **加更多工作维度（项目偏好、协作模式、注意力曲线、压力反应、...）。**
   暂缓。先用 6 个维度跑 4 周看哪些 analyzer 真的产生了**用户会引用的信号**，再决定是否加。**默认收紧不默认扩张。**

## Notes

- analyzer 的 prompt 设计、子维度极轴、合并精度都属于实现细节，归 `docs/architecture/`（待建）或 `cognitive-service/` 下的设计稿，不在本 ADR 范围。
- 重新评估触发条件：4 周后如果某个 work 维度的 entry 命中率 < 5%，说明信号过稀，应合并或删除该维度（再开 ADR）。

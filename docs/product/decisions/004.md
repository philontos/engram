## Context（背景）

讨论"私人副脑"定位时，用户萌生了一个想法：既然 Engram 已经是本地 DB 且跟着自己走，是否顺手把**个人密钥、琐碎信息**也放进来？这样未来迁移办公环境时打包一个 `.db` 文件就能带走全部"我之于电脑"的状态。

提出这个想法时即已自问"这是不是开始做加法了"。本 ADR 把这次诱惑和拒绝固化下来，作为产品纪律的物证。

## Decision（决策）

**拒绝。** Engram **永远**不存：

- API 密钥、token、密码、证书、私钥
- 配置文件 / dotfiles / 环境变量
- 工具 list、安装清单、版本号
- 任何与"我如何思考"无关的事实性 / 状态性 / 凭证性数据

把这条收纳判据上升为 AGENTS.md 硬规则 #1 的展开说明：

> **判断一条数据是否属于 Engram，唯一标准：它是否揭示"我如何思考"。**
> - 揭示思考 → 进 Engram
> - 揭示事实 / 状态 / 凭证 → 不进 Engram，无论看起来多顺手
> - 边界判断不清时，**默认拒**，而不是默认收

## Consequences（后果）

**锁定的事：**

- `entries` 表与 schema 永远不引入"凭证类"字段。
- LLM-facing 工具（agent、MCP、proxy 注入）保持单一数据源，不会在某天意外把密钥送给第三方供应商。
- AGENTS.md 硬规则 #1 在下一次提交里加入"是否揭示我如何思考"展开。

**关闭的可能：**

- Engram 不会演化为"全栈个人数据管家"。即便迁移环境的痛点真实存在，那也用别的工具解决（见 Alternatives 中的工具映射）。

**可接受的副作用：**

- 用户迁移环境时仍需多套工具（Engram + 1Password + dotfiles 仓库）。这是**正确的代价**，不是问题。

## Alternatives considered（被考虑的替代方案）

1. **同意：在 Engram DB 里加 `secrets` 表，加密存储，提供专门的读写工具，对 LLM 屏蔽。**
   被拒。三条具体反对：
   - 违反 AGENTS.md 硬规则 #1（已锁定的"只存认知内容"）。
   - **安全姿态完全不同**：认知内容必须被 LLM 读到（profile 注入、agent context），密钥必须**绝不能**被 LLM 读到。两类数据共存于同一个库，工具调用边界一定有疏漏，迟早泄。物理隔离是唯一安全姿态。
   - **攻击面价值放大**：当前丢一份 Engram DB 是"用户 怎么想"——尴尬。加上密钥后变成"用户 怎么想 + 用户 所有 API key"——严重事故。OSS 项目意味着代码公开，攻击者完全清楚存储结构。

2. **折中：在 Engram 同一个仓库下另起一个独立 DB / module 存密钥。**
   被拒。代码同仓 = 默认共享部署 = 默认共享备份 = 默认共享攻击面。"独立"在工程上几乎无法长期维持，迟早被工具调用打通。要分就分到不同仓库、不同进程、不同部署单元。

3. **只存非敏感的"杂项"（书签、笔记、工具清单），不存密钥。**
   被拒。这是温水煮青蛙的入口。一旦"杂项"开了口子，"啊这条算杂项还是认知"的辩论会反复发生，AGENTS.md 硬规则 #1 在三个月内会被慢慢侵蚀。**保持判据二元**才能长期守住。

## 真实痛点的正确工具映射

用户实际想解决的"环境迁移"痛点用以下工具组合解决，不需要 Engram：

| 痛点 | 错误工具 | 正确工具 |
|---|---|---|
| 密钥跟着环境走 | Engram | 1Password / Bitwarden / age + git |
| 配置 / dotfiles 跟着走 | Engram | dotfiles 仓库 + chezmoi / yadm |
| 工具 list / 习惯 | Engram | dotfiles 仓库里一个 markdown |
| 与 Engram 相关的事实（"我做事看重隐私"） | ✅ Engram | 这条**本来就是认知**，正常 entry 即可 |
| 整体打包迁移 | Engram | `age` 加密 + git，五分钟搞定 |

## Notes

- **本 ADR 的存在本身比内容更重要**。它向未来的自己（和 OSS 读者）证明：这个项目有能力识别诱惑、说出理由、写下拒绝。这是"产品纪律"在 OSS 上最难伪造的物证。
- 同样的诱惑会以其他形式反复出现（"顺便存个 todo 吧"、"加个 reminder 吧"、"记一下我读过的书吧"）。每次都要回到本 ADR 的判据：**是否揭示我如何思考？** 不是 → 拒。
- 重新评估触发条件：**没有**。本 ADR 是"红线类"决策，不设重新评估时点。如果某天用户真要改主意，必须开新 ADR 显式 supersede 本 ADR，把理由写清楚。

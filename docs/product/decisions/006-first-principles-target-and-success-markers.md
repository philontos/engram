## 上下文

长期 maintainer 视角下，实现层思考（dimension / backbone schema 等）逐步覆盖了产品本源思考。STATUS.md 当前的不变项里没有显式的"成功标准"，只有产品边界，导致后续设计无锚。

## 决策

Engram 的第一性目标 = 让一个具体的人在认知 / 方法论上持续升维。成功的双标志 = 判别力（能清晰判断过去判断 / 方法 / 价值的对错）+ 执行力（类似场景做得更好）。

## 当时的理由

没有显式成功标准，后续设计无锚；以"愿不愿意回到过去"为标志过于情感化、多因素；用判别力（能清晰判断对错）+ 执行力（类似场景做得更好）两个外化标志，可对照、可验证、且直接绑定升维的内涵。一年后用户仍处在混沌里 = Engram 失败。这两个标志也对建模 / 采集层提出硬约束：系统必须持有 outcome 数据，否则判别力永远没数据基础。
